# Task context and decisions

1. The user wanted to use a Codex subscription in this Canonry fork instead of requiring an OpenAI API key for every answer-engine connection.
2. The chosen implementation is an **additional provider**, identified as `codex`. Existing API providers stay available. Codex outputs are not labeled as consumer ChatGPT results.
3. The user chose **local Canonry only** and **reuse the existing CLI login only**. No separate OAuth flow, token copying, automatic Codex installation, or API-key fallback.
4. Disconnect must disable Canonry without signing the CLI out. Connection management is an instance-administrator operation. Codex must be explicitly selected; connecting must not expand existing default runs or schedules.
5. The user supplied Gemini and Claude credentials for live baselines. Those credentials and local authentication configuration are intentionally absent from this repository.
6. The user selected **Aurora Solar** as the live target. Twenty fixed queries were selected from `packages/api-routes/test/fixtures/discovery-replay/b2b-saas.json`; the selected strings, source indices, source checksum, domain, aliases, market, and models are frozen in `before/manifest.json`.
7. Before-change capture used one pass each of Gemini 2.5 Flash and Claude Sonnet 4.6. It recorded 40 full responses, normalized snapshots, requested/reported model identity, source evidence, and build identity. Probe runs in an isolated database kept the experiments out of ordinary analytics and notifications.
8. The evidence pilot used five queries through the actual Codex App Server and recovered 22 final source links with matching web-result evidence. Its discovered model was `gpt-5.6-sol`. Production connection later discovered and pinned `gpt-6-astra` for acceptance.
9. The launcher reported `codex-cli 0.144.5`, while the actual App Server initialization reported `0.157.1`. Compatibility is checked against the latter. Public search events do not supply enough attribution; experimental raw events provide the needed web results.
10. Implementation/testing caught and fixed two important attribution issues: hidden Markdown link destinations must not create mentions; model-authored exec output must not be treated as native web evidence. Original Markdown is retained, visible text is normalized separately, and an AST guard accepts only verbatim web-result programs.
11. The live acceptance workload requested 60 Codex answers plus 20 each from Gemini and Claude. It saved 58 Codex and all 40 API-provider answers. Two Codex answers failed closed for unattributed source links. All 58 saved Codex answers were reviewed independently for the target's mention/citation labels and source relevance/support; no label mismatches were found.
12. The full workload precedes the final AST hardening. The hardened path was tested against all 16 pilot tool programs, adversarial fixtures, and one additional live compiled-server smoke query. This distinction is preserved rather than presenting every capture as the same final build.
13. The final user request was to create a branch, push all changes and relevant before/after context, and include a handoff. No merge or production deployment was requested.

Original `.context` captures remain on the originating machine. Published copies remove credentials, private instructions/account state, encrypted reasoning, retrieved-page bodies/source excerpts, and machine-specific paths. Source headers/IDs/URLs and complete model answers are retained. Dependency/build caches and unrelated workspace state are not task deliverables.
